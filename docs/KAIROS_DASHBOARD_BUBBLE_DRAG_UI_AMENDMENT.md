## Browser contract research

Changing touch-action after a gesture starts cannot change that gesture's browser handling; pointer events can be cancelled when the browser takes over panning. This rules out a late CSS switch as the mechanism for a hold followed by free dragging. See [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action).

Touch events can prevent native scrolling on the first touchmove, while explicit passive listeners cannot cancel it. The implementation therefore retains touch-action:manipulation for normal pan/pinch and uses one field-scoped cancellable touchmove only once a stationary hold has armed. Immediate swipes are not cancelled. See [Chrome's scrolling intervention documentation](https://developer.chrome.com/blog/scrolling-intervention) and [MDN Touch events](https://developer.mozilla.org/en-US/docs/Web/API/Touch_events). Browser evidence verifies this behavior on the production renderer rather than relying only on synthetic events.
